1. Make Generate Draft acquisition atomic

The current status check happens before the transaction, so concurrent requests can both pass.

Inside one transaction:
- Resolve/create the canonical Proposal.
- SELECT the canonical Proposal FOR UPDATE.
- After acquiring the row lock, check status.
- If status is proposal_drafting and the generation is not stale, return 409 generation_in_progress.
- Otherwise atomically set proposal_drafting and generation_started_at.
- Only the request that acquired the generation lock may reset/upsert sections and launch AI.
- The second concurrent request must launch zero AI calls and mutate zero sections.
- Validate a supplied proposalId even when no existing canonical Proposal was found.
- Add stale-generation recovery with a defined timeout.

Do not use a pre-transaction SELECT as the concurrency guard.

2. Make session initialization genuinely fail

app.ts currently catches the session DDL failure and resolves dbReady.

Change it so:
- The error is logged without credentials.
- The promise rejects after logging.
- index.ts never calls app.listen when session initialization fails.
- Production exits with a non-zero status.
- Development displays the real non-secret initialization reason in logs.
- Keep the runtime session_save error response:
  503 / session_store_unavailable.

Add a behavioral test where session initialization rejects and assert app.listen is never called.
