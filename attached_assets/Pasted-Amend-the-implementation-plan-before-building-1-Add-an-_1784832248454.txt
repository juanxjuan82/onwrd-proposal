Amend the implementation plan before building:

1. Add an atomic transient `handoff_in_progress` state. Use a conditional database update as the concurrency lock. A second request while this state is active must receive 409.

State transitions:

* No document → `handoff_in_progress` → create and record ID → write content → `handoff_complete`
* Creation fails before an ID exists → clear the transient state so a normal first attempt can retry
* Content fails after the ID is recorded → `pending_first_write`
* `pending_first_write` → atomically acquire `handoff_in_progress` → reset only that incomplete document → populate it → `handoff_complete`
* Completed or legacy linked document → return its URL immediately without acquiring a write lock or calling a Docs mutation

2. A first write may fail after partially inserting content. Do not blindly append during retry. Add a narrowly scoped helper that clears/resets content only when the proposal was explicitly in `pending_first_write`. It must be impossible to call this helper for `handoff_complete`, `synced`, null-status legacy documents, or any other linked document.

`clearAndReplaceContent` must still be removed as a general sync operation. The incomplete-first-write reset must have a separate name and guarded call site.

Add a test where the first write inserts partial content and then fails. The retry must reuse the same document, remove the partial content, write one clean copy, and never call Drive `files.create` again.
