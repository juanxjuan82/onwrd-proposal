## 3. Create one enforceable AI gateway

No route, crawler, scheduler or service should call an AI SDK directly.

Create a single server-side gateway such as:

`artifacts/api-server/src/lib/ai-gateway.ts`

Only this gateway may import the OpenAI client or another model SDK.

Every invocation must declare an allowlisted feature:

* `requirements_extraction`
* `strategy_generation`
* `proposal_generation`
* `section_regeneration`

Reject any unknown feature.

Every invocation must also include:

* User/request context
* Proposal or opportunity ID
* Maximum input size
* Maximum output tokens
* Timeout
* Whether retry is permitted
* A unique operation/idempotency key

The gateway must reject calls without an explicit user-initiated operation. Scheduled jobs, crawlers, imports, scoring and automatic creation paths must never satisfy this requirement.

## 4. Add durable usage and quota protection

Implement persistent database-backed AI usage tracking. Do not rely solely on in-memory counters.

Record:

* Feature
* Opportunity/proposal ID
* Operation ID
* Model
* Status
* Started/completed timestamp
* Input tokens
* Output tokens
* Error code
* User/request identifier where available

Add configurable limits:

* Global daily AI call limit
* Global daily token limit
* Per-feature daily call limits
* Maximum calls per individual operation
* An administrator AI kill switch

Use atomic database checks/reservations so concurrent requests cannot exceed the limits.

If a limit is reached:

* Do not call the provider.
* Return a clear usage-limit response.
* Preserve the proposal and existing work.
* Show when usage may be available again.

## 5. Handle provider quota and rate limits correctly

Classify provider errors using structured status/code fields, not only error-message text.

For `insufficient_quota`, exhausted billing or project-budget errors:

* Open a persistent global AI circuit.
* Do not retry.
* Prevent further AI calls until an administrator resets the circuit or a configured cooldown expires.
* Display a clear message that the connected API project has no available quota.

For temporary rate limits:

* Respect `Retry-After` when provided.
* Allow at most one bounded retry.
* Count every attempted request—not only successful requests—against operation and daily call limits.

A failed request must never create an unlimited retry loop.

* Prevent scheduled/manual overlap
* Release on success and failure
* Never invoke AI
